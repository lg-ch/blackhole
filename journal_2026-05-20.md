## Landed today (in order)

### Storage / build (crash-safe)

- **SRT3 format**: VarByte delta-encoded doc_ids per leaf, byte-offset
  sparse_index. Backward-compat read of SRT2. magic bump 0x53525432 →
  0x53525433. data_bytes in header slot 5.
- **Atomic write**: `.srt.tmp` + fsync + rename. Phase 2 resume = skip
  trees whose `.srt` already exists.
- **xxhash64 footer**: appended after fsync. `rpforest verify <idx>`
  streams + compares. SRT2 indexes pass (no footer = "OK skip"). Tested:
  manually corrupted 4 bytes mid-file, verify catches it.
- **Phase 1 resume**: `phase1.progress` counter persisted every 100k
  vecs, pair files opened "ab" on restart. Killed mid-build → resumes
  cleanly.
- **bvecs format support**: SIFT 1B legacy per-row `[int32 dim][dim u8]`
  reader added.

### FFI + serving

- **libmangrove.so**: full -fPIC build alongside the CLI. ABI: open,
  query, query_multi, query_ids, rerank_l2, n_distinct, tombstones,
  set/get_gen_version, verify_srt.
- **scripts/mangrove_ffi.py**: ctypes wrapper, `Forest` class. ~4 ms/q
  on SIFT 1M, eliminates ~10 ms IPC overhead vs subprocess.
- **scripts/serve.py**: long-running HTTP `/search`, `/health`,
  `/metrics`. Forest lock-serialized (one io_uring ring), CH-down
  graceful degrade. Tested: 10 workers × 200 queries → 198 q/s,
  p99 77 ms, 0 mismatches.
- **scripts/telemetry.py**: pure-Python Prometheus exporter
  (Counter / Gauge / Histogram) without `prometheus_client` dep.

### Mutations (P1 first slice)

- **Tombstones**: persistent CRoaring bitmap
  `<idx>/tombstones.roaring`, AND-NOT composed at query time with the
  caller filter (or flipped to NOT-tombstones if no filter). CLI
  `rpforest delete <idx> <id...>` writes atomic. Persists across reopen.
- Insert-incremental, WAL, compaction: still pending.

### Bench

- **bench_competitive.py** mangrove vs FAISS-IVF+PQ vs hnswlib on SIFT 1M:

  | Engine          | recall@10 | p50 ms | p99 ms | RSS MB |
  | :-------------- | --------: | -----: | -----: | -----: |
  | mangrove        |     0.86 |   8.12 |  22.10 |     39 |
  | faiss-ivfpq     |     0.38 |  0.07  |   0.18 |    558 |
  | hnswlib         |     0.95 |  0.22  |   0.28 |    777 |

  Mangrove wins **RAM/recall**: 20× less RAM than hnswlib for recall
  0.86 vs 0.95.

- **bench under cgroup MemoryMax=100M**: identical numbers, RSS 38 MB.
  Validates the bounded-RAM differentiator.

## Bug noted / not in this commit

- `meta.txt` stores `n_docs = doc_offset + n_vecs` (overstates the pool
  for multi-index shards). Not fixed today — would require a meta format
  bump and isn't blocking SIFT 100M / 1B.
- ROADMAP A1 (filter-aware I/O via leaf min/max ranges) **abandoned**:
  with pairwise-seed traversal, leaves are random samples of
  `[0, n_docs)` → skip rate ≈ 0. Bloom-per-leaf would cost ~8 GB at SIFT
  1B. Filter-aware merge (`cursor_seek_allowed`) is the useful layer.

## Decision: SIFT 1B build params

User's ROADMAP target was 1000 trees × depth 30. Measured rate (200
trees × depth 25 × sub_dim 16) is ~6 K vec/s. Extrapolating to 1B docs:

| Config                | Time est.    |
| :-------------------- | -----------: |
| 1000 trees × depth 30 |    ~14 days  |
| 500  trees × depth 25 |     ~3.5 days|
| 200  trees × depth 25 |     ~30 hours|
| 100  trees × depth 22 |     ~10 hours|

Plan: launch 200 × 25 SIFT 1B build after the 100M run completes;
validate; if recall too low, repeat at 500 × 25.
